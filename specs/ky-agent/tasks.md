# tasks.md — FocusLog Agent 실행 단계 분해

각 Task는 독립적으로 테스트 가능한 단위이며, 1~10분 내 수행 가능한 수준으로 분해되어 있다.

---

## Phase 1. 데이터 수집 설정

### T-01. 세션 시작 및 과목 입력 수신
- **입력**: 사용자가 앱 내 과목 선택 또는 텍스트 입력
- **처리**: `session_id` 생성 + `sessions` 테이블에 `started_at`, `subject` INSERT
- **출력**: `session_id` 반환, 모니터링 활성화 확인 메시지
- **완료 기준**: 과목 입력 후 ≤ 3초 이내에 `UsageStatsManager` 폴링 시작

### T-02. 앱 전환 이벤트 수집
- **입력**: `UsageStatsManager.queryEvents()` 1초 폴링
- **처리**: `ACTIVITY_RESUMED` 이벤트 필터링 → `RawEventQueue` 삽입
- **출력**: `{ app: string, timestamp: ISO8601, event: "app_switch" }`
- **완료 기준**: 앱 전환 발생 후 ≤ 1초 이내에 큐에 삽입

### T-03. 미디어 제목 수집
- **입력**: `MediaSession API` 콜백
- **처리**: 현재 재생 미디어의 `title`, `artist`, `source_app` 추출
- **출력**: `{ title: string, source_app: string, timestamp: ISO8601 }`
- **완료 기준**: 미디어 재생 시작 후 ≤ 2초 이내에 수집

---

## Phase 2. 이탈 탐지 및 분류

### T-04. 이탈 이벤트 감지
- **입력**: `RawEventQueue`의 앱 전환 이벤트
- **처리**: 현재 앱이 학습 화이트리스트(교재 앱, 노트 앱 등)에 없으면 이탈 이벤트 생성
- **출력**: `{ app, started_at, is_distraction: bool }`
- **완료 기준**: 앱 전환 이벤트 수신 후 ≤ 1초 이내에 이탈 여부 판정

### T-05. 이탈 유형 분류 (온디바이스 LLM)
- **입력**: `{ app, title, subject, duration_sec }`
- **처리**:
  1. 앱명 기반 1차 분류 (룰베이스)
  2. 유튜브인 경우 제목·채널명 기반 LLM 2차 분류
  3. 신뢰도 계산
- **출력**: `{ type: DistractionType, confidence: float }`
- **완료 기준**:
  - 분류 완료 시간 ≤ 3초
  - 신뢰도 ≥ 0.60이면 자동 확정
  - 신뢰도 < 0.60이면 T-06 진행

### T-06. 저신뢰도 분류 시 사용자 확인 요청
- **입력**: `confidence < 0.60`인 이탈 이벤트
- **처리**: "이 영상이 [과목]과 관련 있나요?" 팝업 표시
- **출력**: 사용자 응답 (`yes` / `no`) → 분류 확정 + 피드백 저장
- **완료 기준**: 팝업 표시 후 사용자 응답 수신 시 ≤ 3초 이내에 분류 확정

---

## Phase 3. 집중도 점수 산출 및 개입

### T-07. 집중도 점수 실시간 갱신
- **입력**: 확정된 이탈 이벤트 (유형, 체류 시간)
- **처리**: `focus_score = max(0, 100 - Σ(weight × duration_min))`
- **출력**: 갱신된 `focus_score` (0–100 정수)
- **완료 기준**: 이탈 이벤트 확정 후 ≤ 3초 이내에 점수 갱신

### T-08. 개입 방식 결정 및 실행
- **입력**: 갱신된 `focus_score`
- **처리**:
  - ≥ 70: 무개입
  - 40–69: 포모도로 재시작 Notification 발송
  - < 40: 이탈 앱 `DevicePolicyManager` 5분 차단 + 휴식 권고 Notification
- **출력**: `intervention_action`, 알림 발송 여부, 차단 앱 목록
- **완료 기준**: 점수 갱신 후 ≤ 2초 이내에 개입 실행

### T-09. 앱 차단 해제 요청 처리
- **입력**: 사용자 차단 해제 버튼 클릭
- **처리**:
  - 1회차: 차단 해제 + `unblock_count += 1`
  - 2회차 이상: 차단 완전 해제 + `override_log` 기록 + 해당 세션 재차단 금지
- **완료 기준**: 해제 요청 후 ≤ 1초 이내에 차단 해제 실행

---

## Phase 4. 세션 종료 및 리포트 생성

### T-10. 세션 종료 감지
- **입력**: 사용자의 세션 종료 버튼 또는 화면 꺼짐 15분 이상 유지
- **처리**: `sessions.ended_at` UPDATE, 이탈 이벤트 최종 집계
- **출력**: 집계된 세션 요약 데이터
- **완료 기준**: 종료 이벤트 발생 후 ≤ 5초 이내에 집계 완료

### T-11. Claude API 리포트 생성 호출
- **입력**: 세션 요약 데이터 (익명화, 집계 통계만 포함)
- **처리**: Claude API 호출 → JSON 응답 파싱
- **출력**: 리포트 JSON (`summary`, `focused_minutes`, `focused_ratio`, `top_distraction`, `timeline`, `suggestion`)
- **완료 기준**:
  - API 응답 ≤ 30초
  - 타임아웃 시 로컬 템플릿 리포트로 폴백 (≤ 5초)
  - 일 5회 초과 시 로컬 통계 리포트 생성

### T-12. 리포트 저장 및 표시
- **입력**: T-11의 리포트 JSON
- **처리**: `sessions.report_json` UPDATE + 앱 UI 리포트 화면 렌더링
- **출력**: 사용자에게 세션 리포트 화면 표시
- **완료 기준**: 세션 종료 이벤트 발생 후 ≤ 30초 이내에 리포트 화면 표시

---

## Phase 5. 오류 처리

### T-13. 입력 유효성 검증
- **입력**: 모든 외부 입력 JSON
- **처리**:
  - 필수 필드 존재 여부 확인
  - 타임스탬프 형식 검증 (예상: `HH:MM` 또는 ISO8601)
  - 수치 범위 검증 (`duration_sec ≥ 0`)
- **출력**: 유효 입력 통과 / 오류 응답 (`error_type`, `error_detail`, `missing_fields`)
- **완료 기준**: 오류 응답 생성 ≤ 500ms / 부분 정상 데이터는 부분 결과로 반환

---

## 의존 관계 요약

```
T-01 → T-02 → T-04 → T-05 → T-07 → T-08
              T-03 ──┘       T-06 (신뢰도 < 0.60 시)
T-08 → T-09 (차단 해제 시)
T-10 → T-11 → T-12
T-13 (모든 외부 입력에 병렬 적용)
```
