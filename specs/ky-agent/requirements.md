# requirements.md — FocusLog Agent

## 목적

공부 세션 중 스마트폰 앱 전환 로그와 유튜브 시청 정보를 실시간 분석하여, 이탈 유형을 분류하고 집중도 점수를 산출한 뒤 적절한 강도의 개입을 자동으로 실행한다.

---

## 사용자 스토리 (User Stories)

### US-01 · 세션 시작 및 과목 입력
```
나는 대학생으로서
공부를 시작할 때 과목을 입력하면
Agent가 자동으로 모니터링을 시작하기를 원한다.
→ 수용 기준: 과목 입력 후 3초 이내에 모니터링이 활성화되어야 한다.
```

### US-02 · 이탈 유형 자동 분류
```
나는 대학생으로서
유튜브를 열었을 때
Agent가 학습 관련 영상인지 오락 영상인지를 자동으로 구분해 주기를 원한다.
→ 수용 기준:
   - 영상 제목·채널명 기반 분류가 5초 이내에 완료되어야 한다.
   - 분류 신뢰도가 0.60 미만이면 사용자에게 직접 확인 1문항을 요청한다.
   - 신뢰도 0.60 이상인 경우 사용자 개입 없이 자동 분류한다.
```

### US-03 · 집중도 점수 실시간 산출
```
나는 대학생으로서
세션 진행 중 현재 집중도 점수를 실시간으로 확인하고 싶다.
→ 수용 기준:
   - 집중도 점수는 0–100 정수로 표현된다.
   - 앱 전환 이벤트 발생 후 3초 이내에 점수가 갱신되어야 한다.
   - 점수 산식: 100 - Σ(이탈_가중치 × 체류_시간_분)
   - 이탈 유형별 가중치 (5종 전체, steering.md · design.md와 동일):

     | 이탈 유형 | 조건 예시 | 가중치 |
     |---------|---------|------|
     | study_related | YouTube 강의·개념 영상, 학습 앱 | 0.0 (차감 없음) |
     | habitual_check | KakaoTalk ≤ 60초 확인 | 1.5 |
     | avoidance_chat | KakaoTalk > 60초 장시간 대화 | 1.8 |
     | shopping | 쿠팡, 네이버쇼핑 등 | 1.8 |
     | avoidance_entertainment | YouTube 예능·먹방, Instagram, TikTok | 2.0 |
     | unknown | 위 조건 미해당 또는 분류 불가 | 1.0 |
```

### US-04 · 집중도 기반 자동 개입
```
나는 대학생으로서
집중도가 떨어지면 적절한 강도로 개입을 받고 싶다.
→ 수용 기준:
   - focus_score ≥ 70: 개입 없음
   - 40 ≤ focus_score < 70: 포모도로 재시작 알림 (Notification) 발송
   - focus_score < 40: 이탈 앱 일시 차단(5분) + 휴식 권고 Notification 발송
   - 앱 차단은 사용자가 언제든 해제할 수 있어야 한다.
   - 해제 요청이 연속 2회 이상이면 차단을 해제하고 로그에만 기록한다.
```

### US-05 · 세션 종료 리포트 생성
```
나는 대학생으로서
세션이 끝나면 오늘의 집중 패턴을 한눈에 볼 수 있기를 원한다.
→ 수용 기준:
   - 세션 종료 후 30초 이내에 리포트가 생성되어야 한다.
   - 리포트에는 다음 항목이 반드시 포함되어야 한다:
     · 총 세션 시간 (분)
     · 실질 집중 시간 (분) 및 비율 (%)
     · 이탈 이벤트 목록 (앱명, 유형, 체류 시간)
     · 집중도 점수 타임라인 (분 단위)
     · 다음 세션을 위한 개선 제안 1개 이상
```

### US-06 · 실패/오류 입력 처리
```
나는 대학생으로서
입력 데이터에 오류가 있어도 Agent가 조용히 실패하지 않고
오류 원인과 대응 방법을 알려주기를 원한다.
→ 수용 기준:
   - 필수 필드 누락 시 누락 필드명을 명시하고 fallback_log 액션을 실행한다.
   - 타임스탬프 형식 오류 시 오류 위치와 예상 형식을 명시한다.
   - 오류 발생 시에도 정상 처리된 이벤트는 부분 결과로 반환한다.
   - 오류 처리 응답 시간은 500ms 이내여야 한다.
```

## 비기능 요구사항

| 항목 | 기준 |
|------|------|
| 실시간 이탈 탐지 지연 | 앱 전환 이벤트 발생 후 ≤ 3초 |
| 세션 리포트 생성 시간 | 세션 종료 후 ≤ 30초 |
| 온디바이스 분류 신뢰도 임계값 | ≥ 0.60 (미만 시 사용자 확인 요청) |
| Claude API 일일 최대 호출 | ≤ 5회/사용자 (리포트 생성 전용) |
| 데이터 보존 | 세션 로그 온디바이스 보관, 클라우드 전송 없음 |
| 앱 차단 해제 | 항상 사용자 주도로 가능 |

## 병목의 핵심 가치 (steering·design에 반영 필수)

| 가치 | 내용 |
|------|------|
| **병목 원인** | 이탈 후 복귀 지연(평균 23분), 이탈 인식 불가 |
| **암묵 규칙** | 유튜브 = 방해가 아님 (강의 영상은 학습); 카톡 = 항상 방해가 아님 (긴급 응답 가능) |
| **실패 비용** | 2시간 세션에서 실질 집중 40분 → 학습 효율 20%, 반복 시 성적 하락 |
| **개입 원칙** | 강제 차단 없음, 사용자 자율성 최우선 |
